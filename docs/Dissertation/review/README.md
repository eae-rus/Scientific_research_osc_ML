# Сохранение и рассмотрение замечаний

В текущем `planning/source_inventory.json` есть предварительные тексты Word-комментариев, авторы и даты. Это структурная инвентаризация, а не полноценный экспорт: привязки, цепочки ответов и состояние обсуждений ещё не восстановлены. Полным источником остаётся DOCX.

При переносе создать два независимых слоя: `raw/<source_id>/` с неизменёнными частями OOXML и машиночитаемым извлечением; `issues/` с решениями и привязками к новому тексту. Выгрузки генерировать из снимка с зафиксированным хешем.

В рамках задачи **A05** слой сырых замечаний диссертации `DISS-005` полностью выгружен в `review/raw/DISS-005/50516d7832e6ea133d77b11b48802c4ed1929283ea7601134b878fab0e0338f7/`:
- Неизменённые оригинальные части пакета: `comments.xml`, `commentsExtended.xml`, `commentsIds.xml`, `commentsExtensible.xml`, `_rels/comments.xml.rels`.
- Машиночитаемый реестр: `comments.json` (все 144 комментария, авторы, даты, абзацы, вложения и 28 веток ответов).
- Манифест с контрольными суммами: `manifest.json`.

## Схема замечания

| Поле | Содержание |
|---|---|
| `issue_id` | Стабильный ID в диссертации, например `DISS-005-C0144`; не предполагать непрерывность ID Word |
| `source_id`, `source_sha256` | Точная исходная версия |
| `original_comment_id` | Исходный ID Word, сохраняемый буквально |
| `author`, `date`, `text` | Автор, исходная дата и полный текст; отсутствие даты явно обозначать |
| `parent_id`, `thread_id`, `original_state` | Ответы и состояние из расширенных частей; неизвестное состояние не считать открытым или закрытым автоматически |
| `story_part`, `start_anchor`, `end_anchor` | Часть пакета и диапазон, включая таблицы и другие области документа |
| `quoted_text`, `context_before`, `context_after` | Исходный отмеченный текст и окружающий контекст |
| `target_file`, `target_label` | Привязка к перенесённому месту; до переноса может отсутствовать |
| `status`, `decision`, `reason`, `change_reference` | Отдельное решение по диссертации и ссылка на изменение |

Статусы рассмотрения: `new`, `needs_author`, `planned`, `applied`, `declined`, `superseded`. Для последних трёх обязательны объяснение и связь с изменением или заменяющим замечанием. Закрытый в Word комментарий также сохранять: он может содержать полезную мотивацию.

## Контроль полноты

Сопоставить множество ID записей `comments.xml` с диапазонами и ссылками во всех относящихся к документу частях. Проверить повторы, отсутствующие ссылки, границы через несколько абзацев/ячеек, ответы и расширенные метаданные. Несвязанные комментарии сохранить с пометкой `unanchored`, а не отбрасывать. Отдельно проверить отслеживаемые вставки, удаления, перемещения и изменения свойств.

В исходной диссертации 144 записи комментариев и по 144 основных диапазона/ссылки; это стартовая контрольная цифра, не доказательство правильности каждой связи. Для четырёх статей ИИ — 45, 59, 37, 69; для комментированных файлов Энергоинноваций — 11 и 6. Старые версии пока не проверены полностью.

Редакторские заметки в Markdown, `%`-комментарии TEX, сканы рукописных пометок и рецензии тоже включать в реестр с указанием вида источника. Для скана сохранять оригинал и проверенную расшифровку; не выдавать непроверенный OCR за точную цитату. Авторские идеи из основного текста v0.5 сначала переносить буквально, затем по отдельному решению выводить в заметки со ссылкой на прежнее место.
