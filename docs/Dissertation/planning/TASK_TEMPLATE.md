# Шаблон дочерней задачи и отчёта

Копировать только нужный шаблон, заполнять реальными данными. Угловые скобки — места заполнения, не готовые значения. Карточки детей хранить в `planning/tasks/<ID>.md`, отчёты — в `planning/handoffs/<ID>.md`.

## Карточка задачи

```markdown
# <ID> <конкретный результат>

Статус: TODO
Родитель: <ID или нет>
После: <список ID, без собственного родителя>

Цель: <одна проверяемая цель>
Входы: <точные файлы, source_id, sha256, block_id/object_id/comment_id>
Границы: <первый и последний блок, что входит в диапазон>
Разрешённые изменения: <точные файлы или ограниченная новая папка>
Результат: <пути файлов и обязательные поля>

1. <действие над конкретным входом>
2. <действие>
3. <сверка с первоисточником>

Критерии готовности:
- [ ] <проверка с ожидаемым результатом>
- [ ] <проверка покрытия входного списка>
- [ ] <проверка неизменности исходника>

При затруднении: <что сохранить; что является блокером>
Следующая задача: <ID или правило выбора из очереди>
```

## Отчёт и передача

```markdown
# <ID> Отчёт

Статус: <DOING / REVIEW / DONE / BLOCKED>
Исполнитель и сессия: <известный идентификатор или понятное обозначение>
Дата: <дата>
Входы и версии: <пути, SHA-256, ID>
Создано/изменено: <файлы и смысл изменения>
Обработано: <ID и количества, оставшиеся диапазоны>

| Проверка | Метод или команда | Ожидалось | Получено | Доказательство |
|---|---|---|---|---|
| <название> | <воспроизводимый метод> | <условие> | <результат> | <путь и локатор> |

Известные ограничения: <конкретно или не обнаружены в пределах проверки>
Нерешённые вопросы: <ID вопроса, варианты, источник>
Исходники: <результат проверки хешей>
Продолжить с: <точный шаг и файл; для DONE — следующий доступный ID>
Не повторять: <уже выполненные операции, особенно длительные>
```

Для визуальной сверки в доказательстве указывать исходный рендер, целевой PDF, реальные номера страниц/объектов и перечень проверенного. Для научного вывода — цитату/таблицу, файл и локатор, протокол и ограничения; ссылка на целую папку недостаточна.

## Запись вопроса

В `planning/questions.md` добавлять ID, обнаружившую задачу, формулировку, исходные фрагменты и локаторы, варианты решения с последствиями, зависимые задачи и статус `open/answered`. Ответ автора записывать с датой и местом его получения. Пока ответа нет, не менять исходные спорные данные; выполнять независимые части.

## Карточка научного результата

В `planning/integration/claims.json` хранить записи: `claim_id`, формулировка, `source_id`, `source_sha256`, локатор, версия эксперимента, данные/выборка, разбиение, метрика и единица, значение при наличии, ограничения, статус доказанности, личный вклад и основание его атрибуции, целевой раздел.

Статусы доказанности: `reported` (утверждается источником), `verified` (сверено с указанными первичными результатами), `hypothesis`, `conflict`, `unsupported`. Сверка с текстом статьи сама по себе не переводит эксперимент в `verified`. Неизвестные значения хранить как `null` с причиной, не заменять нулём.
