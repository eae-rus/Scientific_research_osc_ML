# Карточки обзора архива и завершения диссертации

Использовать после объединения основных материалов. Задачи описывают работу с диссертацией: они не поручают самостоятельно проводить промышленное внедрение, оформлять фиктивные документы или запускать длительные обучающие эксперименты. Недостающие исследования оформляются отдельными конкретными задачами для автора.

## E01 Составить каталог внешнего архива

**Повторяемая:** одна годовая папка либо один небольшой тематический каталог.

**Вход:** абсолютные корни публикаций и регистрационных документов из `SOURCE_MAP.md`.

1. Перечислить файлы и версии, не изменяя внешний архив. Записать путь, размер, дату файла и SHA-256 выбранных документов; дата файла не является датой публикации.
2. Выделить семейства исследований и точные файловые дубликаты. Файлы с одинаковыми названиями, но разными хешами считать разными версиями.
3. Раздельно отметить статьи, доклады, исходники, рецензии, сканы замечаний, патенты/свидетельства и подтверждения внедрения.
4. Составить предварительный список кандидатов по связи с задачами диссертации; пометить, что отбор по названию ещё не оценка содержания.

**Выход:** `planning/external_archive/catalog.json`, `planning/external_archive/candidates.md`. **Готово:** все назначенные папки покрыты или конкретные недоступные пути перечислены как пробелы; массовое копирование/удаление не выполнялось.

## E02 Изучить и включить выбранные дополнительные исследования

**Повторяемая:** одно семейство, при включении — один небольшой подраздел по процедуре D.

**Вход:** E01, приоритетные кандидаты из SOURCE_MAP и принятый текст.

1. Начать с цикла о поясах Роговского, адаптивных уставок, модели БАВР, материалов RTDS и папки «Для диссера».
2. Для кандидата повторить C02–C05 в необходимых пределах: версия, результаты, комментарии, активы, ограничения и личный вклад.
3. Сопоставить с уже включённым материалом; решить `include/defer/exclude` с обоснованием. Не повторять один результат только потому, что он опубликован ещё раз.
4. Для включения создать малую дочернюю задачу с точным местом и применить процедуру D; для отсрочки назвать недостающие данные.

**Выход:** карточки выбранных источников, решения по кандидатам, проверенные дополнения. **Готово:** все кандидаты назначенного списка имеют содержательно обоснованное решение, а включённые фрагменты прошли проверки. Непрочитанный файл не помечать исключённым «как неважный».

## E03 Проверить регистрационные документы

**Повторяемая:** один документ/одно семейство регистрации.

**Вход:** каталог папки «Патенты», в том числе файлы с номерами 2025621765 и 2025613841.

1. Прочитать сам документ и записать вид, номер, название, авторов, правообладателя, даты и статус ровно в пределах подтверждённых сведений.
2. Различить заявку, уведомление и итоговое свидетельство/патент. Имя папки и файла не служит доказательством вида документа.
3. Связать зарегистрированный объект с конкретным результатом диссертации; не приписывать ему подтверждение эффективности или внедрения.
4. Подготовить библиографическое упоминание и при необходимости материал приложения; сохранить точный источник реквизитов.

**Выход:** `planning/external_archive/registrations.json`, проверенные упоминания/приложения. **Готово:** нет неподтверждённого статуса или ошибочной замены свидетельства словом «патент».

## E04 Собрать факты о применении и внедрении

**Повторяемая:** один из двух контуров — просмотрщик осциллограмм или РНМ для БАВР.

**Вход:** принятые результаты, доступные материалы реализации и испытаний, сведения автора.

1. Найти фактические версии реализации, доступные интерфейсы, инструкции и протоколы. Если программа не находится в этом репозитории, записать недостающий точный вход; не выдумывать функции по названию.
2. Составить цепочку «научный результат → функция → версия реализации → проверка → место применения → документ».
3. Разделить статусы `proposal/prototype/bench/pilot/deployed`; для каждого статуса указать подтверждение, дату и ограничения. Статус выбирать по фактам, не по желаемому названию главы.
4. Для эффекта зафиксировать сравниваемый исходный способ, условия измерения, единицу и источник результата. Отсутствующее измерение отметить явно.
5. Сформировать короткий список конкретных вопросов автору только о неизвестных фактах/документах. Работу по уже подтверждённым данным продолжать.

**Выход:** `planning/implementation/viewer.md`, `planning/implementation/pdr.md`, реестр подтверждений и пробелов. **Готово:** фактический статус обоих контуров установлен настолько, насколько позволяют источники; неизвестное не выдано за внедрение. Инвентаризация может завершиться с явными пробелами, но это не завершает E06.

## E05 Написать главу применения по подтверждённым фактам

**Повторяемая:** один подраздел с одной функцией или сценарием.

**Вход:** E04, исследовательские главы, доступные подтверждения.

1. Описать сценарий инженера в просмотрщике: вход, запуск анализа, представление результата, проверка и действие. Включать только реализованное либо явно маркировать предлагаемое.
2. Для РНМ описать место в логике БАВР, входы/выходы, неопределённое решение и условия применения по фактическому проекту.
3. Сослаться на алгоритмы предыдущих глав вместо повторного изложения их вывода.
4. Описать проверку интеграции и эффект. Разделить длительность окна, задержку обнаружения и время вычисления; не переносить измерение настольного ПК на целевое устройство.
5. Вынести длинные протоколы и документы в приложения с проверяемыми ссылками. Применить обычную процедуру содержательной сверки и сборки D.

**Выход:** глава применения, приложения и `review/checks/implementation-chapter.md`. **Готово:** текст полностью соответствует E04, планы и результаты различимы, алгоритмы не продублированы. Глава может честно отражать незавершённое внедрение; считать общую цель внедрения достигнутой при этом нельзя.

## E06 Проверить достаточность доказательств внедрения

**Вход:** E04–E05, подтверждающие документы и цель автора завершить работу внедрением.

1. Для каждого заявления о внедрении проверить продукт/объект, версию, место и период использования, роль результата диссертации и документальное подтверждение.
2. Проверить, что испытания и измеримый эффект относятся именно к описанной реализации и условиям.
3. Если доказательств недостаточно, составить `remaining_work.md`: конкретное действие, требуемый вход, ожидаемый результат, критерий приёмки и кто может его выполнить. Не создавать акт вместо отсутствующего акта.
4. Отдельно проверить, какие части требуют нового эксперимента, доступа к предприятию или авторского решения. Передать их как реальные внешние зависимости.

**Выход:** `planning/implementation/evidence-audit.md`, при необходимости `remaining_work.md`. **Готово:** заявленное внедрение подтверждено в принятом объёме. Если нет — `BLOCKED` с конкретными пробелами. Это не мешает F01–F05, но блокирует объявление окончательной диссертации готовой в F06.

## F01 Составить матрицу научного вклада

**Вход:** результаты D08, E02–E05, введение v0.5, реестр тезисов.

1. Выписать цель и задачи из исходного текста, затем фактически полученные результаты.
2. Для каждой задачи связать метод, результат, доказательство, ограничения, личный вклад, публикацию, применение и возможное положение на защиту.
3. Отметить задачи без результатов, результаты без задачи и предполагаемую новизну без сравнительного основания.
4. Предложить адресные исправления структуры/формулировок; число положений определять по самостоятельным доказанным результатам.

**Выход:** `planning/contribution_matrix.md`, вопросы о личном вкладе и научной трактовке. **Готово:** каждое предлагаемое положение имеет доказательство и подтверждённую атрибуцию, либо явно не включено в итоговые положения до разрешения вопроса.

## F02 Согласовать факты и научные обозначения

**Повторяемая:** одна группа терминов/результатов, затем итог по всем главам.

**Вход:** F01, весь текст и реестр тезисов.

1. Составить словарь сокращений, обозначений, единиц, классов, типов записи/события/окна.
2. Для повторяющихся чисел найти все места и сверить версию данных, выборку, протокол, знаменатель и округление.
3. Проверить определения train/validation/test, независимость разбиений, каузальность и статистическую единицу оценки.
4. Исправлять только разрешённые картой противоречия. Для неизвестного оставить вопрос и не вводить «единое» число произвольно.
5. Перепроверить связанные таблицы, подписи, введение и выводы после каждого изменения.

**Выход:** `planning/terminology.md`, `review/checks/scientific-consistency.md`, небольшие проверенные правки. **Готово:** нет известных неразрешённых противоречий, затрагивающих итоговые научные выводы. Косметическое единообразие не подменяет согласование протоколов.

## F03 Сделать изложение цельным

**Повторяемая:** один подраздел или один переход между главами.

**Вход:** F02 и актуальный текст.

1. Удалить запланированные повторы аннотаций, вводных обзоров и заключений статей, сохраняя нужные источники и уникальное содержание.
2. Выстроить логику подраздела: задача, основание метода, выполненное исследование, результат, границы результата и связь со следующим шагом.
3. Добавить переходы между инженерной частью, данными, ИИ, РНМ и применением. Не добавлять новые технические утверждения ради плавного перехода.
4. Проверить, что выводы главы следуют из её содержания и не сильнее приведённых доказательств.
5. Сопоставить смысл до/после; редакторская правка не должна менять числа, причинность, степень уверенности или вклад соавторов.

**Выход:** связное изложение и отчёты по партиям. **Готово:** исчезли повторы и разрывы, а доказанные утверждения и ограничения сохранены.

## F04 Согласовать введение положения и заключение

**Вход:** F01–F03 и актуальный статус внедрения.

1. Сверить формулировки цели/задач с матрицей результатов и неизменным названием диссертации.
2. Сформулировать новизну и положения только по подтверждённым результатам; не выдавать планы следующего эксперимента за выполненное.
3. Для каждого вывода заключения указать задачу и раздел с доказательством; убрать выводы без основания.
4. Согласовать практическую значимость с реальным статусом применения. Если E06 не завершён, сохранить ограничение и пометить введение/заключение как требующие обновления перед выпуском.
5. Зафиксировать требующие автора научные формулировки отдельно; не блокировать очевидные редакторские исправления.

**Выход:** согласованные вводная и заключительная части, карта «положение → доказательство». **Готово:** нет несоответствия между заявленным и выполненным; незавершённое внедрение не названо завершённым.

## F05 Проверить оформление по фактическим требованиям

**Вход:** актуальный текст, требования организации/диссовета с происхождением и датой проверки.

1. Получить и прочитать реальные требования. Если их нет, подготовить перечень недостающего; не заявлять нормативную проверку по памяти или названию шаблона.
2. Составить чек-лист: титул и реквизиты, поля/шрифты, нумерация, рисунки/таблицы/формулы, литература, приложения и прочие реально предъявленные требования.
3. Настроить оформление и проверить каждое требование по собранному документу. Название диссертации не менять; реквизиты менять только на подтверждённые.
4. Собрать документ с зафиксированными версиями инструментов; проверить ссылки и лог, затем все страницы визуально.
5. Исправить дефекты, повторить затронутые проверки. Если менялся глобальный стиль, повторить визуальный проход по всему документу.

**Выход:** `review/checks/format-requirements.md`, актуальная сборка и визуальный отчёт. **Готово:** все применимые требования и страницы проверены, нет скрытых дефектов. Без требований допускается только техническая проверка; F05 целиком остаётся незавершённой.

## F06 Подготовить итоговый выпуск и передачу автору

**Вход:** F04–F05, завершённый E06, все реестры и принятые решения.

1. Проверить отсутствие открытых критических вопросов по доказательствам, личному вкладу, внедрению и обязательным требованиям.
2. Сверить все задачи и дочерние задачи: `DONE` подтверждён отчётом; отложенная работа не скрыта под выполненной.
3. Повторно собрать выпуск из зафиксированного набора исходников, проверить состав, ссылки, приложения и соответствие проверенному PDF.
4. Создать `releases/<release_id>/` с итоговыми файлами, манифестом SHA-256, версиями инструментов и инструкцией воспроизведения. Не перезаписывать предыдущий выпуск.
5. Если автор запросил Word для рецензирования, сделать отдельный экспорт, визуально проверить и записать соответствие версии LaTeX. Не создавать вторую независимо редактируемую основу.
6. Передать итог и кратко перечислить выполненные проверки. Если необходимый вход отсутствует, передать честно обозначенную промежуточную версию и сохранить F06 незавершённой.

**Выход:** проверенный выпуск и `planning/handoffs/F06.md`. **Готово:** выпуск воспроизводим, источники и замечания доступны, научные и практические заявления подтверждены в установленном объёме. Наличие собранного PDF без этих условий недостаточно.
