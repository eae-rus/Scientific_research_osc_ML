# RTDS: подготовка заключительной проверки РНМ

## Что проверяется

100 исходных пар CFG/DAT в `data/phase5/_FABT_RTDS`: 1.1, 2.1–2.35,
3.1–3.35, 4.1–4.29. Таблица Г.5 исходного PDF (страница PDF 59, печатная 54)
подтверждает внутренние КЗ на I СШ ЦРП2 только в 2.25 и 2.26, по 0,400 с.
Это длительность, а не время начала КЗ. Границы берутся из дискретного сигнала.
СВ 110 кВ в таблице не следует путать с СВ 6 кВ в осциллограммах.
Это сценарная проверка РНМ, не аттестация всей логики БАВР.

## Запуск

Существующие расчёты и исходные COMTRADE не меняются. Один новый сценарий:
`scripts/phase5_experiments/run_pdr_rtds.py`. Все ручные параметры в начале;
`run_manual()` внизу использует их. Запускать из окружения обучения с PyTorch.

```powershell
# Быстрая подготовка всех исходных сигналов и предварительного эксперта
python scripts/phase5_experiments/run_pdr_rtds.py --prepare-only
# Полная проверка одного опыта всеми органами
python scripts/phase5_experiments/run_pdr_rtds.py --max-records 1
# Все 100 опытов, обе секции, девять РНМ и двенадцать наборов весов
python scripts/phase5_experiments/run_pdr_rtds.py
```

Выход: `data/phase5/pdr_rtds_review`. В консоли номер файла/секции/модели
и число рассчитанных точек, в `progress.json` — прогресс и ETA по файлам.
Начальная оценка ETA приблизительна. Одновременно два запуска в одну папку
запрещены. Полный прогон существенно дороже подготовки, особенно на CPU.
14.09 полный прогон уже запущен в фоне; подробный ход — `generation.log`,
ошибки — `generation_errors.log` в выходной папке. Не запускать второй экземпляр,
пока этот не закончен или явно не остановлен. Первые 100 подготовленных файлов
без ИИ ещё не означают завершения полного прогона: проверять prepare_only и лог.
Продолжение пропускает совместимые готовые пары и опыты, уже перенесённые в
проверенные (включая подпапки); незавершённый файл считается заново.
Не редактировать выход до завершения полного расчёта. Если файл уже изменён
вручную, контроль хешей запрещает его перезапись; для нового прогона выбрать
другой `OUTPUT_ROOT`. Проверенную копию хранить в `data/phase5/pdr_rtds_verified`,
не смешивая её с машинной заготовкой. Исходный `_FABT_RTDS` не трогать.

## Каналы и размерности

| Исходные номера | Содержание | Использование |
|---|---|---|
| 1–3 | I ввода 1, А/B/C | РНМ секции 1 |
| 4–6 | U ввода 1 | Сохраняются для просмотра |
| 7–9 | U СШ 1 | РНМ секции 1 |
| 10–12 | I ввода 2 | РНМ секции 2 |
| 13–15 | U ввода 2 | Сохраняются для просмотра |
| 16–18 | U СШ 2 | РНМ секции 2 |
| 19–21 | Положения ВВ1, ВВ2, СВ | Настоящие дискреты |
| 22 | Наличие КЗ в сети | Границы эпизода КЗ |
| 23–25 | Команды БАВР | Сохраняются как дискреты |

Проверяются и номера, и названия, и фазы; неизвестная схема не принимается
молча. Физическая величина: `(a * DAT + b) * 1000` для кА/кВ. Состояния
проверяются после `a*DAT+b`: округление к 0/1 разрешено лишь с погрешностью
не более 0,0001. Названия сохраняются по-русски (CFG Windows-1251), фазы
в отдельных полях CFG — латинские A/B/C. DAT — COMTRADE 1999 ASCII.

Модель и формульные органы получают I/(3000*20), U/(6000*3).
6000 В — линейный номинал; уже измеренные фазные U дополнительно на sqrt(3)
не делятся. Перевод амплитудного фазора h1 в действующий ток для порога
30 А выполняется отдельно через sqrt(2); в модель второй раз это не вносится.

Наборы весов: weak/expert × snapshot_2/snapshot_5/sequence_1_8 × last/best.
Все двенадцать — из текущих каталогов experiments/phase5, не из архива.
Формульные алгоритмы используют общую реализацию `label_record_multi`.
Неявная замена отсутствующего приватного органа публичным запрещена;
полный прогон требует локального плагина. Закрытый исходник не читается.
ИИ использует общий спектральный кэш одной секции, ранний старт как в галерее;
до полного 20T это диагностический, не обучавшийся режим.

## Предварительный эксперт — согласованные 14.09 правила

1. По умолчанию обычные экспертные FWD=1 и VALID=1; дополнительных каналов подтверждения нет.
2. Все три действующих I первой гармоники <30 А: FWD=0 (высший приоритет).
3. Внешнее КЗ и спад собственного ВВ до 0 в том же эпизоде: FWD=0 на всём
   интервале КЗ, включая время до отключения. Отдельный эпизод не наследует чужое отключение.
4. В 2.25–2.26 на секции 1 КЗ внутреннее: сохраняется 1, кроме малого тока.
5. До первой h1-точки остаётся предварительная 1; отсутствие измерения явно
   учитывается в `seed_reason_counts` JSON. Это не доказанное направление.

Ретроспективная экспертная заготовка не является причинным алгоритмом.
VALID=1 не доказывает пригодность напряжений. В COMTRADE есть отдельные
`S1__expert__FWD/VALID`, аналогично S2. После ручной проверки достаточно
перекрасить нужные зоны и перенести CFG/DAT (желательно и JSON) в папку проверенных.
Именно расположение в `pdr_rtds_verified` означает принятую экспертную разметку.
Служебные счётчики причин находятся
в JSON, а не подменяют экспертный ответ. Дополнительные пользовательские сигналы
при будущем импорте не должны становиться признаками или целями обучения.

## После ручной проверки

Первичная находка для просмотра: Oscilogramma2.25, U первой СШ фаза C,
отсчёты 40188–40191 (индексация с 0), 2,0094–2,00955 с — четыре значения
с модулем >18 кВ, максимум 128443,98 В; 99-й процентиль модуля около 5018 В.
Выброс присутствует в физическом сигнале `a*DAT+b`, не создан нормировкой.
Он не удалён и не признан автоматически ошибкой, но требует инженерного
просмотра. Принудительная экспертная VALID=1 остаётся согласно договорённости.

Первичная проверка из `pdr_rtds_verified` уже доступна:
`python scripts/phase5_experiments/run_pdr_rtds.py --evaluate-verified`.
Она сверяет временную сетку, аналоговые каналы и контрольные хеши неизменных
автоматических дискретов. JSON-сопровождение должно лежать рядом с перенесённой
парой или оставаться в исходной папке экспорта. Из дополнительных пользовательских
каналов ничего не берётся. Результат — `data/phase5/pdr_rtds_evaluation.json`:
поопытные показатели направления, применимости и полного состояния, числа
переключений и среднее по парам «опыт–секция». Обычный импорт Open_EE/French
для этих файлов не подходит. Полноценный анализ задержек ещё предстоит.
Считать отдельно секции, внутренние/внешние повреждения, отсутствие тока,
полную историю/начальный интервал; усреднять также по опытам. Сохранять
ложные разрешения, ложные блокировки, задержки и дребезг, а не только accuracy.
Выбор лучшей эпохи по этим опытам лишит их независимого контрольного статуса.
Раздел 11 статьи подготовлен описательно, без выдуманных результатов.
