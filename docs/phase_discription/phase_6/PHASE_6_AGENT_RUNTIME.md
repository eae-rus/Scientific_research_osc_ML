# Код подготовки корпуса и удалённого агента

Версия 0.3, 17.10.2026. Этот файл — руководство к коду. Рабочий промпт один: EXTRACTION_PROMPT_DRAFT; отдельный словарь — TERMINOLOGY_DRAFT. Оба автоматически входят в каждый `bootstrap.md`; ссылки на примеры настройки из раздела 9 промпта удаляются при подготовке контекста.

## Начать с ноутбука

[030_phase6_corpus_preparation_and_api.ipynb](../../../notebooks/030_phase6_corpus_preparation_and_api.ipynb): корень/выход/годы → подготовка → просмотр сводки → контексты → один API-пилот → пакет → план возврата безымянных файлов. Ячейка сети выключена по умолчанию. Сигналы не читаются и не обрезаются.

Python 3.10+; для текста PDF нужен pypdf, для BMP/TIFF — Pillow, для RAR/7z и старого DOC — 7-Zip (`7z`/`7zz` в PATH или `PHASE6_7ZIP` для DOC). Для страниц PDF нужен pdftoppm в PATH. Минимальные Python-зависимости перечислены в `osc_tools/corpus/requirements-phase6.txt`; SDK OpenAI не требуется. Установка зависимостей в ноутбуке не выполняется автоматически. При отсутствии читателя/рендера ограничение остаётся явным.

## Что делает подготовка

`preparation.py` принимает `PreparationConfig` или JSON `--config`. При output_root=None выполняется подготовка рабочей копии на месте: метаданные в SOURCE_ROOT/_phase6, исходные документы/сигналы повторно не копируются. Готовые неизменившиеся папки пропускаются по отметке и размерам/mtime; verify_unchanged_hashes=True добавляет SHA256. Для отдельного снимка выход и blob должны быть вне исходного корня. Новый выход не затирает существующий. Реестр сохраняет постоянные case-ID; для нового корпуса используйте свой реестр, для этой выборки — `case_registry.json`.

В выходе: `original_inventory.json`, `prepared_inventory.json`, `provenance_index.json`, `archive_manifest.json`, `normalization_plan.json`, `record_index.json`, `_hash_table.json`, `legacy_hash_conflicts.json`, `summary.json`, `cases/<ID>/input`. Пустые файлы остаются в происхождении, в рабочий вход не попадают. Не-PDF бинарный файл нельзя объявить пустым из-за отсутствия текстового слоя. TXT/LOG из пробелов отмечается `text_empty`; оригинал сохраняется.

Архивы сначала перечисляются, затем выбранные типы извлекаются порциями. Сохраняются документальные файлы/изображения/записи и известные служебные контейнеры DEX/OSC/DB/DCF/ALL. Отбор по типу не является смысловой оценкой важности. Ошибка, шифрование, небезопасный путь, лимит или глубина отражаются в манифесте. При необходимости расширить перечень типов — функция `relevant`. Рядовой архив в API целиком не отправляется. Тома RAR начинают извлекаться через part1; результат успешного извлечения выбранного элемента не доказывает смысловое чтение архива.

SHA256-blob хранится один раз; рабочие файлы используют hardlink либо копию при невозможности ссылки. `logical_bytes` — сумма логических экземпляров, `unique_blob_bytes` — сумма уникальных байтов, это не измерение дискового расхода с учётом файловой системы. Общий `blob_root` позволяет нескольким запускам использовать прежние байты. Рабочие входы и blob следует держать только для чтения в процессах агента: изменение hardlink меняет общий blob. Оригиналы с blob не связаны и остаются неизменными.

По умолчанию служебные индексы находятся рядом с подготовленным `input`, а не среди первичных материалов. Если нужно писать их прямо в исходные папки, явно включите `write_source_indexes=True`: появятся `_phase6_provenance.json` и `_phase6_record_index.json`; при следующем проходе они исключаются из входа. Первичные документы при этом не удаляются/не перемещаются. Одиночные справки остаются в корне года, отдельные папки создаются только в рабочем выходе.

Пример CLI из корня проекта:

```powershell
python -m osc_tools.corpus.preparation --config docs/phase_discription/phase_6/preparation_config.example.json
```

Перед запуском отредактируйте корень, выход и годы. `years=[]` означает все найденные годы. Для нового запуска выберите новый выход. Для другого корпуса не присваивайте его папкам старые имена/ID ради похожести: исходный реестр привязан к точным относительным путям.

## Хеши и возврат осциллограмм

`record_identity.py`: ID записи включает хеши известных компонентов; CFG/DAT связываются по имени, DO/D01 — как составная запись. DEX/OSC отмечены `unparsed_vendor_container`; это контейнер-кандидат, количество событий/осциллограмм внутри не определено. Непривязанные DAT/D01 отмечаются отдельно. Содержимое каналов не читалось.

Прежний SearchOscillograms использовал MD5 DAT для COMTRADE и MD5 основного файла для нативного формата. Ключ MD5 сохраняется, но при нескольких папках/конфигурациях все совпадения остаются в новом индексе; старая `_hash_table.json` содержит только однозначные ключи.

После преобразования вызывайте `register_derivative(index_path, record_id, paths, operation, parameters)`: сохраняются новые SHA256 и связь с исходной записью. До регистрации происхождение изменённых байтов из одного прежнего хеша восстановить нельзя. `match_flat` составляет план; `restore_flat` копирует в **новый** каталог с исходной структурой год/папка и сохранённым соответствием case-ID, оставляя оригинал/безымянный набор на месте. Неоднозначности по умолчанию не копируются. В восстановленном наборе `derived/` отличает преобразованные файлы от исходных.

## Как проходит удалённый цикл

Файлы и инструменты находятся на вашем компьютере или сервере приложения. API-модель предлагает вызов функции, код выполняет разрешённый инструмент одной папки и возвращает выбранный текст либо изображение. Этот вариант реализован через [Responses API function calling](https://developers.openai.com/api/docs/guides/function-calling). Для чтения картинки её байты подаются как `input_image`, а не только путь; см. [официальное описание image input](https://developers.openai.com/api/docs/guides/images-vision).

`remote_agent.py` вызывает `/v1/responses` через стандартный HTTPS-клиент. Нет инструмента оболочки, произвольного открытия путей или доступа к соседним комплектам/нашим отчётам. F-ID проверяется по закреплённому манифесту и SHA256. Распаковка выполняется до агента. Работа в пределах папки обеспечивается кодом инструментов; для серверного развёртывания дополнительно ограничьте права процесса и монтируйте первичные входы только для чтения.

Задайте `OPENAI_API_KEY` только в окружении процесса; модель передаётся явно, её доступность и качество надо испытать. Ключ не записывается в JSON/ноутбук. Входные тексты/изображения передаются API-провайдеру при включённом запуске, архивы/полные бинарные сигналы не передаются.

```powershell
python -m osc_tools.corpus.remote_agent --workspace YOUR_COPY/_phase6/agent_runs/api_001/case_000005 --model YOUR_AVAILABLE_MODEL --max-requests 80
```

Этот контекст — G06. Прежние 17 пустых контекстов удалены при очистке 17.10.2026; пересоздай выбранные контексты ноутбуком. Нет ключа/модели — действительный прогон не выполнен. Для своего корпуса используйте новые контексты из ноутбука. При продолжении укажите `--resume`; для независимого повторения создавайте новый `run_name`.

История и encrypted reasoning сохраняются и передаются следующему запросу при `store=False`, согласно [документации reasoning/stateless](https://developers.openai.com/api/docs/guides/reasoning). `store=False` здесь параметр API-запроса, не обещание отсутствия всех видов хранения у провайдера. `remote_checkpoint.json` хранит обмен, SHA256/размер реально отправляемого payload, usage, лимиты и причину остановки. Полный обмен может быть объёмным и содержать первичный текст: это закрытый рабочий журнал.

Один контекст защищён `remote.lock` от двух одновременных циклов. Если процесс оборвался, проверьте, что он завершён, прежде чем удалить оставшийся lock. Остановка посреди исполнения инструмента отмечается отдельно: автоматически повторять потенциально выполненный инструмент нельзя, проверьте state и создайте новый контекст. Сетевые ошибки не повторяются автоматически: запрос с потерянным ответом мог уже расходовать токены. `run_batch` идёт последовательно от новых годов к старым, пропускает `report_submitted`; частичный черновик при этом не становится проверенным.

Лимиты: 256 инструментальных вызовов на контекст; по умолчанию 80 запросов, 16 МиБ на запрос и 12000 выходных токенов на ответ; документы до 32 МиБ, изображение до 8 МиБ. Полный контекст повторяется, автоматически не сокращается. Достижение лимита/ошибка API оставляют явный статус. Сейчас нет автоматического расчёта цены, общего денежного лимита, распределённой очереди или автоматического подбора областей огромного изображения.

`audit` проверяет выдачу текста/цитат и объявленные пробелы, а не правильность технического вывода. `record_image_observation` — заявление исполнителя после получения изображения; само по себе это не доказательство качественного зрения. `submit_report` сохраняет новую редакцию из 12 разделов и карту качества; человек принимает её отдельно.

## Сервер и локальный вариант

Первый запуск можно сделать прямо из ноутбука: хост — ваш компьютер, модель удалённая. На сервер переносится та же кодовая база, подготовленные рабочие входы и контексты; абсолютные пути нужно **пересоздать подготовкой на сервере**, нельзя просто скопировать Windows-манифест и считать его переносимым. Установить 7-Zip/Poppler и Python-зависимости, ограничить каталоги процесса, задать ключ/модель, выполнить тот же CLI. Внешний HTTP-сервис для входящих запросов не требуется для этого worker.

Существующий `.gitignore` исключает `reports/` и `private/`: отчёты, извлечения и подготовленные контексты сейчас сохранены локально, обычный перенос репозитория через Git их не переносит. Сохраните их отдельно для архива/сравнения; рабочие входы агента на сервере пересоздайте из доступного ему корпуса. Наши отчёты в агентский вход не включайте.

Позже файловый слой можно сохранить и заменить транспорт модели; текущий адаптер использует Responses, поэтому локальный сервер с chat-completions не является автоматической заменой одного URL. Нужна проверка/адаптация вызовов инструментов и image input. Веса моделей не скачивались, сервер не развёрнут, реальное API-качество ещё не измерено.

## Что сделать пользователю

1. В ноутбуке указать папки, годы, общий blob-каталог и при необходимости путь 7-Zip; запустить подготовку.
2. Проверить summary/архивные ограничения/список исключённых файлов; не удалять первичные контейнеры только потому, что удалось извлечь один элемент.
3. Задать ключ в окружении, выбрать доступную модель, выполнить один API-контекст G06; затем фото/журналы G07/G08/G12.
4. Оставить конкретные замечания по [17 отчётам и четырём контрольным случаям](reports/README.md). Сейчас приёмки нет.
5. После первого прогона сравнить результаты; при достаточных ресурсах — три новых независимых контекста с одинаковым зафиксированным входом.


## Уточнение 17.10.2026: хранение и готовность

Черновики нынешних 17 комплектов составлены полностью как набор; человеческая сверка, устранение ограничений чтения и реальные API-пилоты ещё впереди. Понятные дополнительные копии по настоящим именам — в `private/phase6/reports`; прежние имена файлов не менялись. История и точные авторские пометки сохранены в `private/phase6/history`.

Для подготовки на месте `PreparationConfig(source_root=..., output_root=None)`. Укажи рабочую копию; обычные файлы остаются на местах, архивные вложения добавляются в `_phase6_extracted`. Одиночные справки объединяются только по точному одинаковому stem в маленькие рабочие группы `_phase6/loose`, чтобы агент не получил целый год. Метаданные и отметки — `_phase6/cases/<ID>`; собственные служебные данные не попадают в документальный вход. Готовность определяется не случайным файлом отчёта, а согласованной отметкой и состоянием источников/извлечений; частичный архивный проход повторно проверяется.

Контексты режима на месте — `_phase6/agent_runs/<имя прогона>/<ID>`, отдельно от выбранной исходной папки. После прогона вызывай `report_export.export_reports`: он сохраняет отчёт/quality/sources/provenance/run по настоящим именам вне контекста, не затирая прежнюю редакцию. Незавершённые контексты не являются удаляемым кэшем, если нужно продолжение. Пользовательские замечания оставляй в сохранённых отчётах.

Поисковик ноутбука 001 теперь использует точное распознавание, поддерживает NDR с WConfig и DEX как непрочитанные контейнеры, копирует родственные компоненты вместе. Из архивов извлекаются только выбранные кандидаты/компоненты и вложенные обычные архивы. Исправлено прежнее условие `or self.PARMA_ZERO_EXTENSION`, которое принимало посторонние файлы за ПАРМА; EXE/SFX не обрабатываются как архив или осциллограмма. Журнал `_search_manifest.json` сохраняет ограничения и происхождение без удаляемых temp-путей; количество групп/контейнеров не равно числу физических событий.

Повтор подготовки на месте сохраняет зарегистрированные производные по record-ID/case-ID. Прежние версии и ранее выбранные годы остаются в индексе с `current_input=False`; `record_candidates` считает текущий выбранный вход, `indexed_records_including_history` — весь сохранённый индекс.
