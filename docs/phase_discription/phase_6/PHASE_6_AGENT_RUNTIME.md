# Инструменты агентского чтения и полных сигналов

Версия 0.1, 9 октября 2026 года. Это инструкция запуска реализованных инструментов. Порядок внедрения, критерии качества и выбор серверного варианта — в [едином плане, §10](PHASE_6_RESEARCH_PLAN.md). Полный агентский цикл с отдельной моделью ещё не испытан; подготовка инструментов не объявляется таким испытанием.

## Что уже работает

[agent_runtime.py](../../../osc_tools/corpus/agent_runtime.py) готовит один комплект по постоянному ID, выполняет ограниченные вызовы инструментов и сохраняет состояние. Протокол — строки JSON через stdin/stdout, без сети. Его можно вызвать из собственного цикла модели или обернуть адаптером выбранной агентской системы. JSONL здесь не назван готовым MCP-сервером или HTTP-сервисом. [signal_export.py](../../../osc_tools/corpus/signal_export.py) запускается отдельным процессом и использует уже существующий OscFormats bridge.

| Инструмент | Что действительно возвращает |
|---|---|
| `get_manifest` | Состав папки, F-ID, SHA256, ошибки учёта, производные изображения |
| `read_document` | Текст с локаторами и диапазонами символов; курсор продолжения при ограничении ответа; отметки оформления |
| `search_document` | Буквальные совпадения в одном источнике и ограниченные фрагменты; остальной текст не отмечается выданным |
| `render_pdf_page` | Один новый PNG выбранной страницы PDF; это рендер, не просмотр |
| `get_image` | Реальные байты изображения в base64; адаптер обязан передать их мультимодальному входу |
| `record_image_observation` | Заявленные область, видимое и ограничение; хост не может сам доказать правильность зрения |
| `add_claim` | Тезис C-ID, модальность, эпизод, точная цитата и источник; цитата проверяется по ранее выданному диапазону |
| `audit` | Покрытие текста по кодировкам, изображения, наблюдения, лимит вызовов; без оценки правильности анализа |
| `submit_report` | 12 разделов структуры v1.1 в новой редакции, карта качества, объявленные и необъявленные пробелы |

Совпадение цитаты не доказывает смысловую правильность тезиса. `all_text_delivered` означает выдачу всех символов, а не понимание. `draft` — сохранённый черновик с технически учтёнными пробелами, а не принятие специалистом. `partial` — остаются необъявленные текстовые или графические пробелы. Вложения DOCX извлекаются лениво, при первом текстовом вызове; их обнаружение не означает просмотра.

## Подготовка и протокол

Из корня проекта, используя Python среды проекта:

```powershell
python -m osc_tools.corpus.agent_runtime prepare --inventory "private/phase6_review/agent_pilot_20261009_212459/corpus_inventory.json" --case-id case_000007 --output "private/phase6_review/NEXT_RUN/case_000007" --instruction "docs/phase_discription/phase_6/PHASE_6_EXTRACTION_PROMPT_DRAFT.md" --vocabulary "docs/phase_discription/phase_6/PHASE_6_TERMINOLOGY_DRAFT.md"
python -m osc_tools.corpus.agent_runtime schema
python -m osc_tools.corpus.agent_runtime serve --workspace "private/phase6_review/NEXT_RUN/case_000007"
```

`NEXT_RUN` заменяется новым идентификатором. Повторная подготовка существующей папки запрещена; для продолжения используется `serve` с прежней папкой. Реестр берётся из последнего запуска с резервом D020, ID не назначаются заново. Текущая команда подготовки работает с физическими папками из `cases`; подготовленный отдельно D020 пока требует отдельного адаптера происхождения.

Пример одной строки входа:

```json
{"id":"call_1","tool":"read_document","arguments":{"file_id":"F0004","start":0,"offset":0,"max_chars":6000,"encoding":null}}
```

Ответ имеет `id`, `ok` и `result` либо `error`. В продолжение текста передаются `start`/`offset` из `next_cursor`. Количество совпадений поиска не превращается в число событий. Не передавать `get_image.image_base64` как обычную длинную текстовую строку: адаптер преобразует его в поддерживаемый выбранной моделью image input. Поддержка зрения проверяется отдельно.

Файл `bootstrap.md` содержит параметры, полный словарь и полную инструкцию, кроме раздела случаев настройки со ссылками на прежние отчёты. Он является входом новой модели. `manifest.json` фиксирует исходники; `state.json` сохраняет вызовы, диапазоны текста, цитаты и наблюдения. Кэш этого запуска находится в `extractions`; кэш прежнего анализа не подставляется. Каждое сохранение создаёт `reports/revision_XXXX/`, не перезаписывая прежнюю редакцию.

Ограничения первой реализации: 256 вызовов на папку; текстовый ответ до 16000 символов и 50 блоков; изображение до 8 МиБ, без инструмента обрезки области; запрос JSONL до 2 МиБ; основной файл документа до 32 МиБ. Остановка по лимиту возвращает ошибку и сохраняет след. Изменение лимита — действие оператора, не инструмента модели. Параллельные изменения одного `state.json` не поддерживаются: один владелец процесса на комплект. Массовой очереди, сетевой аутентификации и подключения модели здесь ещё нет.

## Полная сигнальная ветка

```powershell
python -m osc_tools.corpus.signal_export --workspace "private/phase6_review/NEXT_RUN/case_000007" --output "private/phase6_review/NEXT_RUN/case_000007/signals" --bridge "build/osc_formats/OscFormats.dll"
```

Сохранение происходит в новый каталог. Выход — метаданные каналов и `samples.bin`: сначала float64 little-endian время, затем все аналоговые каналы float64, затем все дискретные каналы uint8, каждый канал целиком. Проверяются все отсчёты, размер потока, строгое возрастание времени, конечность аналогов и диапазон дискретов 0/1. Это формат существующего bridge, а не новый парсер производителей. Восстановление повреждённых хвостов отключено.

Исходники остаются на месте; экспорт сохраняет весь интервал, все каналы и исходную частоту, без сегментации, фильтрации и прореживания. A/B уже применены bridge; повторная калибровка запрещена. Отметки возможных эпизодов позднее хранятся отдельной таблицей интервалов. График или производное окно не заменяет полной записи. Совпадение хешей потоков не доказывает тождество событий; DFR/NDR могут быть входами частей одной собранной записи.

В этой итерации подключён строгий native bridge; COMTRADE получает явный статус `reader_not_connected`. Следующий адаптер должен переиспользовать `load_oscillogram`, сохранив тот же контракт полного потока. Существующий Python-загрузчик не импортируется автоматически в среде без Polars. Для NDR требуется соответствующий WConfig рядом; чужая конфигурация не подставляется. Успешный экспорт не означает проверенной связи с эпизодом и не переносит диагноз из справки на все сигналы.

## Серверная среда и проверенный пилот

Текстовый хост использует стандартную библиотеку и существующий модуль чтения. PDF требует pypdf; рендер страниц — Poppler; DOC — 7z/7zz в PATH либо `PHASE6_7ZIP`. Сигнальная ветка требует опубликованного OscFormats и .NET runtime; сборка и установка при чтении не выполняются. На сервере задаются свои пути; Windows-пути текущего реестра не переносимы без явного обновления корня и повторной проверки относительных файлов/SHA256. Эта инструкция не подтверждает развёртывания на Linux.
