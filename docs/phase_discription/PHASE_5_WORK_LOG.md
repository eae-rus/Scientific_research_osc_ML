- **Реструктуризация открытых алгоритмов РНМ по 4 фундаментальным физическим принципам**:
  - Дублирование по "брендам производителей" заменено на **4 физических алгоритма**:
    1. `PhasePDRAlgorithm` (`phase_pdr_basic`, `basic_phase.py`) — пофазный угловой алгоритм с поддержкой `quadrature_90` ($I_A \leftrightarrow U_{BC}$) и `direct` ($I_A \leftrightarrow U_A$) поляризаций.
    2. `PositiveSequencePDRAlgorithm` (`pos_seq_pdr_basic`, `basic_pos_seq.py`) — угловой алгоритм прямой последовательности $U_1, I_1$.
    3. `PhasePowerPDRAlgorithm` (`phase_power_pdr_basic`, `basic_phase_power.py`) — пофазный мощностной алгоритм 90° схемы (Механотроника БМРЗ-БАВР).
    4. `PositiveSequencePowerPDRAlgorithm` (`pos_seq_power_pdr_basic`, `basic_pos_seq_power.py`) — мощностной алгоритм прямой последовательности (SEL 32P / ЭКРА 217 / ABB 32R).
- **Универсальное восстановление 3-х фазных и 3-х линейных напряжений** (`osc_tools/pdr/voltage_utils.py`):
  - Реализована функция `derive_unified_voltages`, автоматически вычисляющая 3-е линейное напряжение из **абсолютно любой пары из 3-х возможных комбинаций** ($U_{AB}+U_{BC}$, $U_{BC}+U_{CA}$, $U_{CA}+U_{AB}$).
  - Добавлено автовычисление эквивалентных фазных напряжений $U_A, U_B, U_C$ при отутствии фазных каналов, что делает все 4 алгоритма прозрачными для работы от 2 линейных напряжений.
- **Стандартизация логики БАВР, памяти предыстории и уставок**:
  - В `osc_tools/pdr/base.py` обновлен стандарт выходов БАВР:
    - **`FORWARD (1)`** = БЛОКИРОВКА БАВР ($P > 0$, мощность в нагрузку) $\implies$ `is_tripped = True`.
    - **`REVERSE (0)`** = РАЗРЕШЕНИЕ БАВР ($P < 0$, мощность в сеть / выбег двигателей) $\implies$ `is_tripped = False`.
    - **`UNLABELED (-999)`** = Неразмеченная/невалидная зона (начальный прогрев БПФ / отсутствие данных).
  - Память $U_{mem}$ переходит на первую доступную БПФ-точку записи ($N_{fourier} \ge 1$), если глубина предыстории -200 мс еще не накопилась.
  - Уставка по углу зафиксирована равной $\varphi_{mch\_deg} = 45.0^\circ$ во всех 4 физических органах.
  - Уставка по мощностному моменту 3-фазной сети выверена с учётом линейно-фазного коэффициента $\sqrt{3}$: $P_{thresh} = \sqrt{3} \cdot 1.0 \cdot 0.05 = \mathbf{0.0866\text{ о.е.}}$.
  - В `voltage_utils.py` добавлена функция `scale_thresholds_for_profile` для автопересчета уставок под профили входных каналов (`dataset_internal`: деление на 20 по току, на 3 по напряжению и на 60 по мощности).
- **Обновление реестра и документации**:
  - `PDRRegistry` обновлен на 4 физических класса.
  - Переписан [`PUBLIC_PDR_ALGORITHMS_DESCRIPTION.md`](file:///d:/Программирование/Fork/Scientific_research_osc_ML/osc_tools/pdr/public_algorithms/PUBLIC_PDR_ALGORITHMS_DESCRIPTION.md).

## 24.07.2026 — Анализ результатов предобучения модели Heavy (pretrain_b_heavy, 4.8M параметров)

- Проведён детальный анализ прогона 200 эпох тяжелой модели (`pretrain_b_heavy`, `d_model=256`, 8 слоёв, `d_ff=1024`, ~4.8 млн параметров):
  - **Динамика сходимости**: Модель показала превосходную стабильность на протяжении всех 200 эпох. Достигнут абсолютный минимум валидационного loss **`0.0003019` на 99-й эпохе** (снижение общей ошибки на **-15.6%** по сравнению с `small`).
  - **Стабилизация источников**: Рассогласование Open_EE и French/RTE полностью ушло: Val Open_EE достиг минимума `0.0003256`, Val French = `0.0003596`. К 199 эпохе Open_EE остался на уровне `0.000458` (в 3 раза лучше, чем у `small`).
  - **Метрики по группам признаков** (`eval_phase5_pretrain.py`):
    - Фундаментальная $h_1$: `0.0036899` (-23.8% по сравнению со `small`).
    - Низшие компоненты $lp$: `0.0002053` (-37.1%).
    - Прямая последовательность: `0.0004230` (-42.3%).
    - Токи / Напряжения: `0.0005836` (-22.1%) / `0.0002308` (-27.9%).
  - **Эффективность GPU**: Пропускная способность составила `73.84 samples/sec` (около 5 мин/эпоха), а пиковое потребление VRAM составило всего **`210.6 МБ`** (2.6% от 8 ГБ RTX 3060 Ti). Чекпоинт весит `95.5 МБ`.
- **Выводы**: Увеличение емкости полностью подствердило гипотезу. Короткая длина последовательности (`snapshot_5` = 5 токенов) позволяет беспрепятственно масштабировать `d_model` и число слоев без потери скорости.

## 24.07.2026 — Полномасштабное ревью и доработка адаптивного органа РНМ (БАВР)

- **Результаты глубокого ревью кода РНМ** (`docs/phase_discription/PDR_CODE_REVIEW.md`):
  - Проведено сопоставление реализованной Python-версии с эталонным C-кодом прошивки БАВР `PDRF.c` из проекта `mir`.
  - Устранено расхождение в пофазном режиме: заменена логика «ИЛИ» на строгий принцип **«И» (AND)** (`forward_count == valid_phase_count`). Общий сигнал РНМ выставляет `FORWARD` (1) только при прямом направлении во всех 3 фазах.
- **Полная адаптивность прямой последовательности** (`private/pdr_algorithms/adaptive_pdr.py`):
  - Режим прямой последовательности (`rnm_type = "positive"`) выставлен в качестве основного режима по умолчанию для БАВР.
  - В метод `_compute_positive` полностью внедрены 3 типа адаптивностей по фазорам прямой последовательности $U_1, I_1$:
    1. Адаптивность угла максимальной чувствительности ($\varphi_{mch}$) по углу нагрузки из предыстории за 10 периодов.
    2. Адаптивная зона срабатывания ($\alpha_{pos}, \alpha_{neg}$) в зависимости от величины тока $I_1$.
    3. Адаптивный порог по току ($I_{abs\_thresh}$) на основе предыстории тока за 10 периодов.
  - Уставка предыстории параметризована в периодах сети (`history_periods = 10.0`), что делает алгоритм универсальным для любых частот дискретизации.
  - Выведены все конфигурационные параметры из ПО терминалов БАВР в `tunable_parameters`.
- **Подробное математическое описание закрытого алгоритма** (`private/pdr_algorithms/ADAPTIVE_PDR_ALGORITHM_DESCRIPTION.md`):
  - В закрытый каталог `private/pdr_algorithms/` добавлен подробный документ с описанием всех шагов, математических формул, порогов и уставок адаптивного алгоритма БАВР.
- **ТЗ для веб-исследования сторонних производителей** (`docs/phase_discription/PDR_MANUFACTURERS_RESEARCH_BRIEF.md`):
