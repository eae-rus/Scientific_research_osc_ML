# Что включать в итоговый отчёт по комплекту материалов

Версия 0.3 для обсуждения, 8 октября 2026 года. Основание: [план](PHASE_6_RESEARCH_PLAN.md), [разбор примеров](PHASE_6_EXAMPLES_REVIEW.md), авторские примечания. Инструкция будущей модели: [черновик промпта](PHASE_6_EXTRACTION_PROMPT_DRAFT.md).

Назначение — сохранить максимально качественное описание события или событий, чтобы далее пользоваться им для поиска, анализа, обсуждения и подготовки стандартных черновиков. Комплектом считается папка с вложениями либо отдельный документ. Этот текст задаёт содержательную структуру; генератор и окончательный JSON-контракт пока не реализованы.

## 1. Один отчёт с разной глубиной чтения

Предлагается один основной документ: краткая сводка → подробное описание → проверяемые приложения. Это позволяет быстро просмотреть результат и затем читать детали. Реестр фактов может храниться рядом как служебное представление; обязательной второй самостоятельной «карточки» для человека нет.

Полнота означает сохранение доступного существенного содержания, а не заданный объём текста. При малом объёме данных правильный итог может быть коротким. Не добавлять общие рассуждения и типовые объяснения для заполнения разделов. Рассказ ведётся прямо о событии; «автор сообщает» нужно только при предположении, споре или различии источников. Метод получения сведений и отсутствие новой проверки сигналов объявляются отдельно. Не нужно перечислять подписи, весь журнал работы ПО или руководство эксплуатации. Значимые сведения вне заранее заданных полей допускаются в отдельном разделе.

## 2. Краткая сводка

В начале указать:

- ID комплекта, версию результата и границы разбора.
- Какие события выделены и на каком основании; если группировка предварительная — это явно написано.
- Что произошло по основным источникам, существенные действия и последствия.
- Какие редакции использованы; существенное расхождение, если оно меняет итог.
- Что ограничивает описание: отсутствующие сведения, непрочитанные материалы, спорные выводы.
- Пригодность для предполагаемых задач, отдельно от качества текста.

Необходимая формулировка для комплекта только с записями: «Описание по справке недоступно; найденные файлы записей в этом проходе не анализировались». Имя папки можно привести как подсказку, но не как установленный сценарий.

## 3. Подробное описание каждого события

| Блок | Содержание и существенные ограничения |
|---|---|
| Контекст | Роли объектов, участок и напряжение, исходное состояние схемы; источник текстовый или визуальный |
| Развитие | Связное описание начального состояния, процессов, изменений и последующих эпизодов; причинные связи только с основаниями |
| Хронология | Время в исходной записи, точность, последовательность, относительные интервалы; время документа, регистрации и импорта отдельно |
| Действия РЗА и оборудования | Субъект/комплект, функция, пуск, команда, отключение, включение, отсутствие действия и его объяснение |
| Авторская оценка | По конкретной функции и эпизоду; правильное, отказ, ложное/излишнее, предположительное, не приведено |
| Параметры | Значение, единица, контекст, измерение/расчёт/уставка; неизвестная шкала не дополняется |
| Причины | Наблюдение, объяснение автора, степень определённости и результат позднего обследования раздельно |
| Последствия и мероприятия | Реальные последствия, выполненные действия и предложения автора различаются |
| Существенное вне шаблона | Необычная, но полезная информация без принудительного отнесения к готовому классу |

Основной текст использует роли и профессиональные функции вместо длинного перечня марок. Но «защита линии на стороне A», «защита линии на стороне B» и разные комплекты не сливаются. Точные обозначения остаются в приложении и локаторах.

Для длинной цепочки полезна таблица эпизодов. Не задаём обязательное число эпизодов: различаем физическое развитие, действия персонала, реакции устройств и изменение условий. При недостатке сведений порядок может быть известен без точных времён. Не добавляем время «для стройности».

## 4. Различия редакций и источников

Привести источники основной сводки и основание приоритета. Выбранная отметка «Завершённая» должна быть действительно прочитана, а не взята из ряда вариантов шаблона или суффикса имени.

Существенные различия показывать таблицей: положение → источник/версия A → источник/версия B → влияние на описание → состояние разрешения. Уточнение списка сигналов и изменение причины — разная глубина изменения. Документ другого формата не становится независимым подтверждением, если это копия той же редакции.

Если версии несовместимы и приоритет не установлен, описать общую согласованную часть, затем обе позиции. Более поздняя дата файла не разрешает спор. Поздний протокол измерения может подтвердить дефект на дату проверки, но не автоматически доказывает его роль в прежней аварии.

## 5. Записи и связность комплекта

Раздельно показать:

1. Что автор сообщает о наличии, отсутствии или недоступности записей.
2. Какие файлы действительно найдены, включая компоненты составных записей и контейнеры.
3. Какие записи прочитаны и какие связи проверены; если этого не было — прямое ограничение.

Ссылка на файл из отчёта полезна, но одинаковое имя встречается у разных устройств. Полный локальный путь и роль источника необходимы для различимости. Совпадение папки или даты — основание кандидата связи. Несинхронизированные часы сохраняются без автоматической подгонки; различие времени не обязательно означает другое событие.

Число файлов не равно числу осциллограмм: CFG/DAT — компоненты; DO/D01–D05 — возможный комплект; дополнительные экспортные форматы могут описывать ту же запись. Не объявлять количество подтверждённых записей до соответствующей проверки.

## 6. Изображения и схемы

Для каждого существенного изображения или группы однотипных изображений указать: источник, предполагаемую/распознанную роль, глубину просмотра, что прочитано, что не удалось, вклад в описание. Групповой обзор допустим, но значимые выводы должны иметь локатор конкретного изображения.

| Статус | Что можно утверждать |
|---|---|
| Обнаружено, не анализировалось | Только наличие и метаданные; содержимое не описывается по имени |
| Обзорно просмотрено | Общий вид материала; точные надписи, строки и соединения могут остаться нечитанными |
| Частично прочитано | Только названные страницы/области/надписи; остальные ограничения сохраняются |
| Существенные области прочитаны | Доступные наблюдения с локаторами и оговорками; это не экспертная проверка всего изображения |
| Нечитаемо или недоступно | Причина и возможный способ повторной проверки |

Фото кабеля не само по себе доказывает электрический механизм ложной работы. Схема вторичных цепей не сама по себе описывает их состояние в момент события. Скриншот списка событий не равен расшифрованной хронологии. Отдельно записывать видимое на изображении и интерпретацию автора справки.

Если модели сложно понять изображение, она должна сказать, какая часть не понята и почему. Не требуется рисовать новую схему. Большой комплект схем можно читать выборочно по вопросу, сохраняя границы охвата.

## 7. Приложения для проверки и обновления

Реестр источников: устойчивый локальный ID, исходник/вхождение, роль, версия, метод и охват чтения, ошибки, причина пропуска. Временные файлы, пустые приложения, неизвестные форматы и содержимое контейнеров учитываются с отдельными статусами.

Достаточны компактные ссылки на исходные документы, разделы и значимые области изображений внутри итогового отчёта. Для текущих образцов отдельный реестр утверждений и многочисленные временные файлы не обязательны. При необходимости автоматизации служебный реестр может хранить ID, событие/эпизод, субъект, формулировку, исходное выражение, модальность, источник/локатор и состояние проверки. Не обязательно повторять весь текст справки; достаточно минимального подтверждающего контекста и возможности открыть исходник. Для Word страницы не угадываются; используются таблица/строка/ячейка, абзац либо проверенный рендер. Для изображения — реальная страница и область.

Сводка прохода: что прочитано, что намеренно не читалось, что не удалось; инструменты, версия инструкции и модель при автоматизации. После сохранения проверяемого результата восстановимые промежуточные представления могут очищаться по согласованной политике.

## 8. Неизвестное и доказательность

Различать: не приведено; явно отсутствует по источнику; не применимо с основанием; найдено, но не прочитано; неоднозначно; источники противоречат; связь не установлена; возможно проверяемо позже.

«Нет осциллограмм» обычно отражает отсутствие сохранённых/полученных данных или невозможность регистрации; дополнительных механизмов не придумывать. Область утверждения сохранять, если указано конкретное устройство. Реальные файлы и упоминания сверять отдельно, без автоматического объявления документа ошибочным.

Для спорного утверждения желательно объяснить: чего не хватает, что влияет на итог и каким материалом это можно проверить. Гипотезы допустимы отдельным необязательным блоком, с основаниями и альтернативами. Отсутствие полезной гипотезы не является неполнотой отчёта.

## 9. Профиль качества и сложности

| Характеристика | Предлагаемое представление на первом пилоте |
|---|---|
| Охват источников | Числа учтённых, прочитанных и частичных материалов с перечнем существенных пропусков |
| Полнота содержания | Контекст, развитие, действия, причины, последствия: раскрыто/частично/неизвестно с объяснением |
| Доказательность | Прямое утверждение, авторское предположение, спорное, ограниченное чтением, проверено специалистом |
| Сложность события | Описание эпизодов, длительности, взаимодействия функций и объектов без произвольной суммы баллов |
| Сложность материалов | Разные редакции, много объектов, расхождения часов, трудные изображения и форматы |
| Пригодность | Для каждой задачи: предварительно пригодно / условно / недостаточно / не оценено, с причиной |

Пример: «Описание причин подробно по справке; изображения просмотрены обзорно; один BB найден, сигналы не прочитаны; для поиска и стандартного черновика предварительно полезно; для обучения по осциллограмме пригодность не установлена». Это точнее единого числа 0,9.

Пороговые баллы обсуждаем после примеров. Даже отсутствие противоречий не доказывает физическую истинность авторского вывода.

## 10. Граница будущего обучающего описания

В полном отчёте сохраняются все полезные сведения. Для будущей задачи отдельно отмечается источник знания: справка, журнал, изображение, последующее обследование, сигнал после его проверки. Потенциальная наблюдаемость и фактически проверенная наблюдаемость — разные статусы.

Позднее для конкретного входа составляется допустимый целевой ответ: что этот набор сигналов/изображений действительно может поддержать, где нужен дополнительный контекст и где корректен ответ «не установлено». Сейчас такой ответ по сигналам не создаём без их анализа.

Стандартный черновик справки составляется из подтверждённой части итогового отчёта. Пустые поля шаблона, неподтверждённые классификационные коды и выводы специалиста не достраиваются автоматически. Входной набор будущей модели и границы её задачи должны быть явно названы.

## 11. Форма, проверяемая на текущих образцах

Порядок: краткое описание → развитие → действия и параметры → вклад изображений → различия редакций → неизвестное и пригодность → удаляемые служебные сведения. Пустые блоки можно опускать с кратким объяснением; число разделов не является обязательной длиной. Образцы: [G07](phase6_examples/G07_EVENT_REPORT.md), [G12](phase6_examples/G12_EVENT_REPORT.md).

В основной части: роли, технически полезные уровни напряжения, фазы, параметры и относительное время. В служебной: объект и конкретные присоединения, исходные дата/год/часы, марки устройств, точные внутренние обозначения, пути, имена записей и ссылки. Люди и подписи исключены полностью. Граница конкретных технических обозначений уточняется по образцам; удаление служебной части не объявляется готовым разрешением публикации.

T0 объявляется явно: например, первая сигнализация по справке. Он не равен установленному началу физического процесса. Относительные интервалы не приобретают точность лучше исходных часов. Для самостоятельной проверки служебная часть сохраняет отображённые времена и их вид.

Итоговое описание не включается обратно в список первичных источников собственного события при повторном проходе. Генерируемый результат и авторские материалы должны различаться происхождением, даже если позже лежат рядом.

Устойчивые формулировки берутся из [словаря](PHASE_6_TERMINOLOGY_DRAFT.md); неизвестное выражение сохраняется для обсуждения. Нормализация терминов не разрешает расширять содержание диагноза.
