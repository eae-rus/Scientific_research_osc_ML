# Phase 5 PDR: разметка, анализ и ручной запуск

Это единая инструкция вместо прежних отдельных руководств по датасету и анализу.
Актуальный контракт для новой разметки — **v5**. Версия v4 сохраняется
только до завершения контроля v5.

## Семантика меток v5

- `FORWARD=1` и `REVERSE=0` — два обучающихся класса.
- `UNLABELED=-999` — не третье направление. Такие точки обучают отдельную
  выход применимости (`target_applicable=0`), но не попадают в функцию потерь,
  оценку согласия направления и функцию потерь запаса.
- Нет двух токов для восстановления трёх фаз — `UNLABELED`.
- Токи измерены, но равны нулю/ниже уставки — `REVERSE`.
- Нет восстанавливаемой группы U или все фазные U ниже `0.05 Uном` —
  `UNLABELED`. Одна просевшая фаза не маскирует всю точку.
- Адаптивный MIR может определить направление по памяти U, если текущее U
  пропало. До накопления 10T памятью служит самая ранняя FFT-точка;
  после 10T берётся `t-10T`.
- Для будущего экспертного слоя исходная разметка сохраняется без временного
  сдвига. Точка перехода `expert__VALID` или валидного `expert__FWD` и следующие
  5 мс исключаются только из supervised loss и образуют отдельный transition
  evaluation subset. Сигнал из этих отсчётов не удаляется из входного контекста.

Внутренний порог U для `dataset_peak_phasor` равен
`0.05*sqrt(2)/(3*sqrt(3))`: учтены фазная база, reserve=3 и peak-фазор.
Токовая уставка публичных органов: `0.05*sqrt(2)/20`.

## 1. Smoke-разметка

Открыть `scripts/phase5_experiments/run_pdr_dataset_study.py`, в `run_manual()`:

```python
SMOKE = True
```

Запустить файл. Результат: `data/phase5/pdr_labels_v5_smoke`.
После завершения проверить `status=complete`, наличие всех пяти органов,
отсутствие разогрева адаптивного органа после первого окна Фурье и ненулевое покрытие.

CLI: `python scripts/phase5_experiments/run_pdr_dataset_study.py --smoke`.

## 2. Полная разметка

После пробного запуска изменить `SMOKE = False` и запустить тот же файл. По умолчанию:

- Open_EE + French/RTE, все части разбиения;
- все пять органов;
- `SAMPLE_STEP=1` — решение на каждом исходном отсчёте;
- `RECORDS_PER_SHARD=64`;
- lossless-сжатие включено;
- выход: `data/phase5/pdr_labels_v5`.

Повторный запуск с тем же хэшем конфигурации безопасно продолжает готовые фрагменты.
Другой контракт не смешивается с каталогом. Прерывание Ctrl+C теряет только
незакрытый фрагмент.

Наблюдение из другого PowerShell:

```powershell
while ($true) {
    Clear-Host
    Get-Content data/phase5/pdr_labels_v5/open_ee/progress.json -Raw
    Start-Sleep -Seconds 5
}
```

Не держать `progress.json` открытым блокирующим редактором. Код повторяет
атомарную замену при кратком Windows-lock.

## 3. Основной анализ

После обоих `status=complete` открыть
`scripts/phase5_experiments/analyze_pdr_dataset_study.py`. В `run_manual()` уже заданы:

```python
MODE = "all"
LABEL_DIR = PROJECT_ROOT / "data/phase5/pdr_labels_v5"
OUTPUT_DIR = PROJECT_ROOT / "data/phase5/pdr_analysis_v5"
```

`all` последовательно строит сводку, точное согласие с временной статистикой и
комбинациями пяти органов, аудит сигналов, фактическую маску пригодности 2I+2U,
затем диагностические PNG/CSV. Маска объединяет provenance с наличием конечных
значений, поэтому должна считаться после аудита сигналов. По
умолчанию выбирается 20 примеров на группу
и окно 0,8 с. `FORCED_CASES=(("open_ee", 44574), ("french_rte", 44))`
добавляет два ранее разобранных спорных случая независимо от нового рейтинга.
Выход: `data/phase5/pdr_analysis_v5`.

Расширенный расчёт согласия стал тяжелее прежнего: он дополнительно считает
временные показатели адаптивного органа на уровне записей и 32 возможные
комбинации пяти органов. При этом в памяти остаётся только один фрагмент
разметки; прогресс показывается по фрагментам отдельно для каждого источника.
Не запускать этот этап до состояния `complete`
обоих источников и не запускать параллельно второй экземпляр анализа в тот же
`OUTPUT_DIR`.

## 4. Научные проверочные таблицы

После основного анализа запустить
`scripts/phase5_experiments/review_pdr_analysis_results.py`. Его `run_manual()` читает
`pdr_analysis_v5` и добавляет:

- токовые диапазоны в физических `I/Iном`;
- профили источников и частей разбиения;
- чувствительность к дубликатам;
- кластерный бутстреп по уникальным хэшам;
- полный список устойчивых расхождений;
- профили `источник × SPP × f_adc` и чувствительность выводов к способу
  взвешивания осциллограмм;
- пояснение статистических метрик, эмпирические функции распределения,
  тепловые карты и диаграммы
  комбинаций пяти органов.
- паспорт обеих популяций (`all_input` и `pdr_eligible_2i2u`) и data dictionary;
- метод главных компонент и нагрузки, устойчивость KMeans по пяти
  инициализациям, изолирующий лес;
- классификатор различия источников, калибровка и корреляции Спирмена с BH-FDR.

Научный обзор использует только `pdr_eligible_2i2u` для содержательных выводов о РНМ,
но сохраняет все входные записи в паспорте качества. На полном v4 расчёт
многомерного слоя занимает около минуты.

## 5. Удаление старых версий

`pdr_labels_v4`, `pdr_analysis_v4` и созданный из них каталог ручного обзора не
удалять до выполнения всех условий:

1. v5 имеет состояние `complete` для Open_EE и French/RTE;
2. число записей/окон совпало с ожидаемым;
3. анализ v5 завершён;
4. выборочные PNG, запись 44574 и French/RTE record 44 проверены;
5. подтверждено, что последующий код открывает v5.

После этого v4 становится кандидатом на удаление. До того момента ничего
в старых каталогах вручную не удалять и не перезаписывать.

## 6. Отбор и экспорт COMTRADE для ручной разметки

Открыть `scripts/phase5_experiments/export_pdr_manual_review_comtrade.py`.
Первый запуск оставить безопасным:

```python
EXPORT_COMTRADE = False
```

Он создаст:

- `data/phase5/pdr_manual_review_v5/candidate_catalog.csv` — все записи и все
  подходящие страты, без ограничения единым списком первых N;
- `selection_preview.csv` — следующий неповторяющийся пакет по квотам.

Квоты `QUOTAS_PER_SOURCE` задаются отдельно для устойчивого расхождения,
фазных/последовательностных органов, пяти диапазонов переходов, околопорогового/большого тока,
аномалий и слепого контроля. Внутри каждой группы выбираются различающиеся по
физическим и временным признакам представители. Один файл экспортируется один
раз, даже если входит в несколько страт.

Для первой проверки программы рекомендуется временно задать одну квоту и имя:

```python
QUOTAS_PER_SOURCE = {key: 0 for key in DEFAULT_QUOTAS}
QUOTAS_PER_SOURCE["persistent_disagreement"] = 1
EXPORT_COMTRADE = True
BATCH_NAME = "pilot"
```

Это даст не более одной Open_EE и одной French/RTE записи. После успешного
открытия вернуть `QUOTAS_PER_SOURCE = dict(DEFAULT_QUOTAS)` и
`BATCH_NAME = None`; пилотные записи автоматически исключатся.

Полный запуск с `EXPORT_COMTRADE=True` создаёт новый каталог
`batch_YYYYMMDD_HHMMSS`, содержащий полную длительность каждого случая, CFG/DAT,
сопроводительный JSON-файл и `batch_manifest.csv`. Аналоговые каналы записываются в A/В через
явные базисы нормировки; пять РНМ и эксперт имеют пары `FWD+VALID`.

Уже экспортированные записи определяются рекурсивно по сопроводительному JSON-файлу и имени CFG.
Поэтому готовые пары можно сортировать внутри `pdr_manual_review_v5` по любым
подпапкам (`accepted`, `ambiguous`, `rejected` и т.п.): следующий запуск их не
выберет. Не удалять сопроводительный JSON-файл и не переименовывать только один файл пары.

Перед массовой ручной разметкой открыть по одному Open_EE и French/RTE файлу в
целевой программе и проверить длительность, масштаб А/В, фазировку и сохранение
дискретных каналов. Обратный импорт будет реализован после фиксации формата, в
котором программа сохраняет изменённые экспертные дискреты.

Готовую экспертную разметку не следует смешивать с исходными `batch_*`.
Рекомендуемая структура статусов, правила переноса комплектов CFG/DAT/JSON и
контракт будущего обратного импортёра приведены в
`docs/phase_discription/PHASE_5_MANUAL_LABELING_GUIDE.md`.

Текущая целевая квота Open_EE выше French/RTE в два раза: Open_EE ближе к
схемам БАВР, а French/RTE используется как внешний домен и источник ёмкостных
режимов. Экспортёр дополнительно просматривает `pdr_manual_labels_v1`, поэтому
`completed`, `ambiguous` и `invalid_quality` не выбираются повторно даже после
удаления исходного автоматического пакета.

Если у отдельной Open_EE-записи отсутствует физический базис `Ip_base`/U-base,
она записывается в `export_failures.csv` и больше не выбирается автоматически.
Остальной пакет продолжается. При прерывании уже готовые sidecar автоматически
собираются в восстановленный манифест на следующем запуске.

## 7. Обратный импорт экспертной разметки

Запустить:

```powershell
& 'C:\ProgramData\anaconda3\python.exe' `
  'scripts\phase5_experiments\import_pdr_manual_labels.py'
```

Сценарий проверяет все статусы, но в обучаемый слой включает только:

- `completed` — обе экспертные головы;
- `invalid_quality` — только отрицательную цель применимости.

`ambiguous` остаётся в аудите и не участвует в loss. Дополнительные каналы
внешней программы допускаются и регистрируются, но не используются. Выход:
`data/phase5/pdr_expert_labels_v1`.

После каждого изменения ручных CFG/DAT этот этап нужно повторить. Он безопасно
пересобирает только компактный производный экспертный слой, не изменяя
`pdr_labels_v5` и исходные COMTRADE.

Основные таблицы:

- `record_audit.csv` — фактическая разметка каждой записи;
- `algorithm_comparison.csv` — сравнение с пятью РНМ и 95% cluster-bootstrap;
- `record_algorithm_comparison.csv` — полный пофайловый рейтинг;
- `expert_quality_flags.csv` — кандидаты слепой перепроверки;
- `expert_group_summary.csv` — сводка по источникам, статусам, split и стратам;
- `records.csv` — сохранённый research-strict split.

## 8. Первый цикл обучения РНМ

Сценарий: `scripts/phase5_experiments/run_phase5_pdr_training.py`.

Сначала проверить weak-stage:

```powershell
python scripts/phase5_experiments/run_phase5_pdr_training.py `
  --stage weak --temporal-mode snapshot_5 `
  --label-stride-samples 5 --smoke
```

Затем запустить полный weak-stage без `--smoke`. По умолчанию используется
SSL-checkpoint `experiments/phase5/pretrain_b_small/best_model.pt`; Open_EE
получает вес 0,8, French/RTE — 0,2.

После появления `best_model.pt` выполнить smoke и полный expert-stage:

```powershell
python scripts/phase5_experiments/run_phase5_pdr_training.py `
  --stage expert --temporal-mode snapshot_5 `
  --label-stride-samples 5 `
  --weak-checkpoint experiments/phase5/pdr_weak_snapshot_5_stride5/best_model.pt `
  --smoke
```

Для полного expert запуска убрать `--smoke`. Он использует 75% экспертных
примеров и 25% replay Open_EE; внутри экспертной части Open_EE получает 75%,
French/RTE — 25%. Исходные validation/holdout не переносятся в train.

После базовой пары повторить абляции:

1. `snapshot_2`, шаг метки 5;
2. `snapshot_5`, шаг метки 2;
3. `sequence_1_8`, шаг метки 5;
4. шаг 1 — только контрольный дорогой прогон после оценки времени.

Аугментация первой версии не меняет пороги: применяется только совместная
циклическая перестановка фаз и общая смена полярности U/I. Шум и амплитудное
масштабирование пока запрещены, потому что около уставки способны изменить
физически правильную цель.

Текущее окружение `C:\ProgramData\anaconda3\python.exe` пригодно для импорта,
но на проверенной машине не содержит PyTorch/Polars. Обучение следует запускать
из того же окружения проекта, в котором выполнялись предыдущие Phase 5
pretrain-эксперименты. В начале сценарий выводит ошибку до создания checkpoint,
если PyTorch отсутствует.
