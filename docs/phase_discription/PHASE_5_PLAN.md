# План Фазы 5: Self-Supervised Pre-training на реальных данных + Дообучение

-> **Статус:** В разработке (build)
**Цель:** Обучить Physical KAN-Transformer на большом объёме реальных (неразмеченных) осциллограмм методом self-supervised learning, а затем дообучать на конкретные задачи (ДПОЗЗ и др.). Фаза 5 является логическим продолжением Фаз 4/4.5.

---

## 🎯 Ключевые концепции

1. **Два этапа обучения:**
   - **SSL pretrain** — на реальных неразмеченных данных (Open_EE_Dataset + французский датасет) → модель учится понимать форму осциллограмм в целом.
   - **Fine-tuning** — на конкретных задачах с разметкой (симулированные ОЗЗ, РНМ-разметка и т.д.) → дообучение под целевые задачи.

2. **Мульти-датасетность:** Обучение одновременно на нескольких источниках данных с возможностью задавать веса сэмплинга.

3. **Ленивая загрузка:** Данные слишком велики для RAM (~47 ГБ Open_EE + 2 ГБ French + 62 ГБ Simulated_OZZ). Требуется chunked/streaming загрузка.

4. **Адаптивный LR scheduler:** Переход от фиксированного косинусного к современным адаптивным подходам (ReduceLROnPlateau, CosineWarmRestarts, OneCycleLR).

     - `proportional`: веса пропорциональны числу осциллограмм
     - `balanced`: равные веса для каждого датасета
     - `custom`: пользовательские веса

4. **Адаптивные параметры окна:**
   - [ ] `window_size = window_periods × SPP` (всегда 10 периодов)
   - [ ] `stride = stride_periods × SPP` (по умолчанию 1/8 периода — как в последней версии сети для ОЗЗ)
   - [ ] Для разных SPP: разные `window_size` и `stride` → разные размерности входа
   - [ ] Частота дискретизации должна быть обработана на входе и с её учётом посчитаны частоты / спектр сигнала

**Выход:** Универсальный датасет для SSL pretrain на нескольких источниках с ленивой загрузкой.

## ⚠️ Риски и ограничения

1. **RAM 64 ГБ:** При загрузке `unlabeled_50_1200.csv` (18 ГБ) в RAM может не хватить. Решение: NPZ + mmap_mode='r' или чанковое чтение. Большие датасеты разбиваются на группы по 100-1000 осциллограмм для удобства ленивой загрузки (а может и каждый по отдельности - обдумать это).

2. **VRAM 8 ГБ:** При разных SPP (24 vs 32 vs 128) размер входа модели меняется. Нужно проверить, что модель влезает в VRAM при максимальном SPP. Для низких частот может не получиться считать высшие гармоники — тогда прост писать 0. Так же у низких частот может не укладываться шаг в 1/8, придумать как это решить, вероятно, прост дублировать значения с предыдущей выборки

3. **Нормализация французских данных:** Номинал тока неизвестен. Предлагаю сперва собрать статистику по 1-й гармонике, провести анализ, а потом принять решение. По напряжению всё понятно (90 кВ), а вот по току нужно думать.

4. **Совместимость с Phase 4:** Новые датасеты не должны ломать существующий пайплайн. Обязательны regression-тесты.

5. **Размер Open_EE_Dataset:** 47.5 ГБ в CSV. Конвертация в NPZ может занять часы. Нужно планировать время.

- **Размер окна:** stride = 1/8 периода (не 1/2 как ранее планировалось) — выровнено с финальной сетью для ОЗЗ.
